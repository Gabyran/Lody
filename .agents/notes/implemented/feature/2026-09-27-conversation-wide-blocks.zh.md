# 对话中的宽内容块

Status: implemented
Translation: current

[English](2026-09-27-conversation-wide-blocks.md)

## 摘要

对话栏把内容限制在 768px，让正文保持易读的行长；但表格、代码、图表、diff 和终端输出的
排版由内容决定，即使面板两侧还空着几百像素，它们也只能在栏内横向滚动或折行。现在当面板
宽度不小于 1024px 时，这类块会提供一个切换按钮，点击后按内容需要变宽，居中于阅读栏，只受
面板宽度限制，宽度变化带动画；不能折行的独立公式会自动变宽。让所有块自动变宽的方案实现后
在审阅中被否决：宽度不同的块起点各不相同，视线需要反复寻找下一行的开头。这部分重新审视了
[阅读对比度决策](2026-09-24-reading-contrast.zh.md)中“所有块都留在栏内”的结论。

## 问题

`CONVERSATION_CONTENT_WIDTH_CLASS` 把每一行都限制在 768px。这个宽度适合正文，却不适合
排版由内容决定的块：八列表格的每个单元格都在折行，长代码行需要横向滚动，从左到右的
流程图被裁在滚动条后面，由对齐列组成的终端输出在列中间折行。桌面面板上阅读栏两侧的
空白一直闲置。

## 决策

- **是否变宽由读者决定。** 表格、代码块（包括 `diff` 代码块）、Mermaid 图、工具 diff 和
  终端输出默认保持栏宽，读者点击 `WideBlockToggle` 后才变宽，再点一次恢复。已有按钮的块
  把它加进现有按钮组（代码块工具栏、Mermaid 操作栏、表格悬停时与“复制”并排的按钮、工具
  diff 的文件头）；终端没有按钮，所以它在悬停时出现在右上角。图标：变宽用
  `UnfoldHorizontal`，恢复用 `FoldHorizontal`。
- **独立公式自动变宽。** 公式不能折行，而且是作为一个整体来读的。
- **按钮只在有用时出现**：在对话流内、面板宽度不小于 1024px，并且块的内容比块宽（有内容
  横向滚动，或表格单元格、终端行发生折行），或者块已经处于变宽状态。窄表格、短代码块和
  自上而下的流程图都不显示按钮。
- **多宽**：`calc-size(max-content, min(size, 上限))`，不窄于阅读栏。上限
  `--conversation-wide-block-max-width` 为面板宽度减去两侧的大纲导轨和 18px 边距
  （`100cqw - 136px`），没有绝对上限，所以块正好停在内容不再需要滚动条的位置。
- **放在哪**：所有候选块（包括收起状态）都带 `left: 50%` 加 `translate: -50%`，在栏宽时
  两者相互抵消，因此只有宽度在做动画（220ms，缓出）。`calc-size()` 让宽度可以插值；WebKit
  不支持，会直接跳变。开启“减少动态效果”时关闭过渡。
- **范围**：只包括助手正文中的顶层 Markdown 块，以及活动行里的工具 diff 和终端。正文、
  列表、引用、图片、用户消息、嵌套的 Markdown 块和带边框的面板（计划、工具内容里的
  Markdown、各种卡片）都不会变宽。
- 移除了原先针对 diff 的变通做法（整条助手行横向滚动、最小宽度 480px）；溢出由 diff 块
  自己处理。

## 职责

- `ai-gui/wide-block-toggle.tsx` 负责按钮本身：根据自身位置找到所属的块，判断该块是否
  符合条件、是否需要更多空间，并在块上设置 `data-wide-expanded` 属性。
- `tailwind/index.css` 负责几何：居中、宽度过渡、展开后的宽度、独立公式的自动变宽，以及
  变宽和按钮共用的 1024px 面板门槛。
- `lib/conversation-layout.ts` 负责上限（`conversationWideBlockMaxWidth`）；
  `ai-gui/view.tsx` 在对话流的滚动容器上设置该上限和 `data-conversation-wide-scope`。
- 承载按钮的位置：`markdown-code-block.tsx`、`markdown-table.tsx`、`markdown-renderer.tsx`
  （Mermaid 操作栏 portal）、`terminal-component.tsx`（`wideToggle`）和 `DiffViewer` 的
  `headerAccessory`。

## 备选方案

- **自动按内容宽度变宽**：最先实现，并在应用中审阅。每个块的起点横坐标不同，阅读起点
  不断移动。除独立公式外都否决了。
- **自动变宽并加 72rem 上限**：也试过；在大屏上 `diff` 代码块停在 1152px，在空白旁横向
  滚动。出于同样的原因，按需变宽的版本也不设绝对上限。
- **所有块都留在栏内**：即阅读对比度决策的结论。宽内容继续在空白边距旁横向滚动或折行。
- **始终显示按钮**：在已经放得下的块上，一个点了没效果的按钮只是干扰；只在内容比块宽时
  才出现。
- **用负 margin 代替 transform**：需要事先知道块的最终宽度，而宽度由内容决定；只有
  transform 能让未知宽度的块居中。

## 验证与局限

- 在 Storybook 中用 Chromium 145 验证（`Sessions/SessionConversationPage` → Desktop
  Reading Review，1600px 视口，面板 1150px）：除独立公式（966px）外，所有块初始都是
  768px。宽表格、长代码行、`diff` 代码块、从左到右的 Mermaid 图和终端出现按钮；窄表格、
  短代码块和自上而下的流程图没有。变宽后：表格 955px（内容宽度），代码行、Mermaid 和终端
  1014px（面板上限）；按钮文字变为“收回到阅读栏宽度”。逐帧采样一个变宽中的代码块：
  768 → 855（27ms）→ 976（94ms）→ 1014px（约 220ms）。在 1000px 视口下所有按钮隐藏，
  包括公式在内的所有块都保持 768px。
- 把上限变量调到 3000px 模拟大屏面板时，长代码行停在 1224px，正好等于它的滚动宽度。
- 在平移后的块中，Mermaid 的点击激活和以指针为中心的双指缩放仍然正常。
- 工具 `DiffViewer` 在无头 Storybook 中不渲染正文，改动前后都是如此，所以它的按钮和变宽
  效果没有被观察到；文件头按钮和 shadow root 溢出检查已经就位。
- 块的变宽状态保存在按钮里，Virtua 卸载该行后会丢失，与代码块的换行开关一样。
- 没有单元测试：jsdom 不计算布局，无法在其中观察块是否需要更多空间以及块的宽度。
